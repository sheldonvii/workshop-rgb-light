# 控制器配置与迁移

本文补充 [README 快速开始](../README.md) 中的控制器准备步骤，介绍权限、WLED 设置、灯光参数和排障。

## 连接与权限

已验证的控制器为 WLED-Controller-S2，固件 WLED 0.15.1，原生 USB CDC，30 颗 RGB 灯珠。首次部署先完成下面步骤，再启动 Demo。

1. 使用可传数据的 USB 线连接控制器，执行 `ls -l /dev/serial/by-id/` 查找设备。若没有串口，检查数据线、USB 端口和固件的 USB CDC 支持。
2. 检查串口所属组和运行用户权限。K3 上设备属于 `root:dialout`，首次配置执行下方命令，将实际运行 Demo 的用户加入 `dialout`。需要 sudo 认证，但不要用 sudo 运行整个 Demo。
3. 重新登录 SSH／桌面会话，再运行 `id` 确认包含 `dialout`。已运行的服务也要重启才能获得新组权限。新板子、新系统或更换运行用户时需要重新检查，同一用户日常启动和 USB 插拔无需重复配置。
4. 修改 `configs/light.json`，使 `port`、`led_count` 与实际设备一致。优先用 `/dev/serial/by-id/…`，不要假定始终是 `/dev/ttyACM0`。启动后页面应显示控制器已连接。

```bash
# 请替换为实际运行 Demo 的用户；本项目板端用户为 bianbu
sudo usermod -aG dialout bianbu
# 退出并重新登录后检查
id
ls -l /dev/serial/by-id/
test -r /dev/serial/by-id/usb-WEMOS.CC_LOLIN-S2-MINI_0-if00 && \
test -w /dev/serial/by-id/usb-WEMOS.CC_LOLIN-S2-MINI_0-if00 && echo SERIAL_ACCESS_OK
```

如果目标系统的设备所属组不是 `dialout`，请使用实际组名。使用 systemd 部署时确认 `User=` 为已授权用户；必要时配置 `SupplementaryGroups=dialout` 并重启服务。不要用 `chmod 666` 开放串口，也不要将密码写入脚本或仓库。

## 灯光配置

参数保存在 [configs/light.json](../configs/light.json)，修改后重启服务。

| 配置 | 默认值与含义 |
| --- | --- |
| `enabled` | `true`；没有实体灯带时可改成 `false`，网页和推理仍可运行 |
| `port` / `led_count` | 当前设备的固定路径 / `30`；连接时会查询 WLED，数量不一致则停止输出并提示 |
| `brightness` / `standby_brightness` | `0.60` / `0.06`，单人或不同表情 / 待机的 RGB 缩放系数 |
| `group_mode` | `cycle`；整灯按情绪轮换。可改 `spatial` 使用逐灯珠分区渐变；设置抽屉可临时切换 |
| `group_brightness` | `[0.78, 0.95]`，2～3 人 / 4 人及以上全部稳定且同一表情时的亮度 |
| `standby_color` / `transition_ms` | `#EAB7CF` / `400` 毫秒；无可靠情绪时使用待机光 |
| `fps` / `keepalive_ms` | 渐变最多每秒 `30` 帧；稳定颜色每 `1000` 毫秒补发一次 |

单人和不同表情使用 60%，全员一致时按人数提高至 78% 或 95%。有人待确认、暂离或保留旧色时不增亮。待机为粉色 `#EAB7CF`、6%。这些值是 RGB 缩放系数，实际亮度还受 WLED 总亮度、电流限制和灯带影响；95% 不代表电气安全保证。

分区模式按画面从左到右分配等长灯区，邻接处短距离混色。整灯模式依次呈现不同情绪，每种停留时间为人数 × 1.2 秒，上限 2.4 秒，其中包含 400 毫秒换色过渡，不使用呼吸或频闪。镜像开关会在下一帧调整灯区顺序。沿线颜色占比按表情人数汇总，背景保留相同比例；灯带输出条显示后端逐像素轨迹。配置 30 颗只表示发送 30 个地址，能否看见空间分色取决于实际灯珠接法。本次实物红蓝分区及交换测试表现为整灯先红后蓝，未观察到同时分色，因此当前配置默认整灯轮换，分区模式保留供后续灯带使用。

| 表情 | 灯色 | RGB 色值 |
| --- | --- | --- |
| 开心 | 日光黄 | `#FFD000` |
| 惊讶 | 琥珀橙 | `#FF780A` |
| 平静 | 青绿色 | `#00D9A6` |
| 难过 | 深蓝色 | `#246BFF` |
| 生气 | 朱红 | `#FF2010` |
| 害怕 | 紫罗兰 | `#8000FF` |
| 厌恶 | 饱和绿 | `#55DD00` |
| 轻蔑 | 玫粉色 | `#FF269C` |

## WLED 设置与供电

配置修改后重启服务。WLED 中需先设好灯带类型、颜色顺序、GPIO 和灯珠数量；仓库 v1.0 原理图的数据引脚为 GPIO38，实际板卡以其原理图为准。WLED 实时接收超时必须大于补发间隔，建议保持 2500 毫秒；关闭其他实时控制来源和实时接管屏蔽。软件不会自动重刷固件或改写 WLED 的持久设置。

控制器连接前会使用串口 JSON **只读查询**版本和数量，日常灯色、渐变与保活均为 Adalight 二进制帧，不走 Wi-Fi/HTTP。此控制器是 5V 设计，灯带电压、灯珠数量与供电应匹配，不能把 12V/24V 接入其 5V 口；长灯带按功耗独立供电，不默认由 K3 USB 承担。

## 运行与退出行为

未开始体验、停止或暂停时输出待机光。每个人独立确认，短暂不确定或离开保留旧色 900 毫秒，超时后退出颜色占比；全部失效后渐变回待机。页面显示暂离或保留标记，多人框使用各自情绪色。其他页面可查看状态，但同时只能有一个体验会话控制灯光。

验证实际灯珠寻址时，先停止服务，等待 WLED 实时接收超时，再运行 `.venv/bin/python tests/preview_pixels.py --run`。脚本依次输出红蓝分区、交换分区、空间渐变、移动绿区和全灯渐变，每个比较图案默认 15 秒，最后恢复待机。结束后重新运行 `./run.sh`。测试输出使用约 25% 通道强度，与表情亮度分开。

服务运行期间 USB 断开会提示并每两秒重试，恢复后发送最新状态。退出整个服务或进程异常退出后不再补发，WLED 在自身实时超时后恢复原有灯效；这与网页点击停止后保持待机光不同。USB 成功写入表示数据已交给设备，不等于光学反馈，首次迁移还需现场核对颜色和接线。

网页的连接状态指 K3 与 USB 控制器之间的通信。“配置 N 颗灯珠”来自 WLED 配置，不是检测到的实物数量。三线灯带没有连接反馈，拔掉控制器到灯带的接线或灯带独立电源时，USB 控制器仍可在线；软件不能据此判断灯带是否连接或发光。

## 故障排查

| 现象 | 检查方法 |
| --- | --- |
| 串口无权限 | 检查当前进程用户的 `id`；加入组后重新登录或重启服务 |
| 没有设备／设备繁忙 | 检查数据线和固定路径，关闭串口终端、刷机工具及其他 Demo 进程 |
| 灯珠数量不一致 | 同时核对 WLED 设置、实际灯带和 `led_count`，不要只改一端 |
| 能连接但颜色不对或不亮 | 检查 WLED 的 GPIO、灯带类型、颜色顺序、总亮度、实时设置及电源 |

协议参考：[WLED 串口接口](https://kno.wled.ge/interfaces/serial/)、[控制器仓库](https://github.com/wuxx/WLED-Controller-S2)。
